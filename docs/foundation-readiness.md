# 基础准入与迭代顺序

本页将[需求 R01–R19](requirements.md)变为开发顺序，防止 AI 围绕辅助记事功能持续扩张。地基建设的完成以证据为准；硬件、真实外网和用户试用仍需真实执行。当前结果统一见[项目状态](project-status.md)。

## 前期交付与准入

| 地基项 | 交付 / 通过条件 | 当前下一动作 |
|---|---|---|
| 需求 | 已确认的用户、主链路、优先级、逐项验收；变更同步需求和 ADR | 每个任务声明 R 编号，不擅自重定义产品 |
| 架构 | app/domain/Mac adapter、权限及数据所有权；请求/状态/终态设计 | 复用已实现的[产品边界](architecture.md)，验证设备链路和实际能力子集 |
| 代码质量 | Swift 6 并发、显式错误、可注入边界、格式和行为回归；生成工程可重建 | 单一命令 `./scripts/check.sh`，iOS 执行 `./scripts/test-ios.sh` |
| 性能 | Release 合成工作负载、原始样本、p50/p95、严重退化门禁；设备指标独立 | 执行 [性能规范](standards/performance.md)中的真机计划，记录失败和长文本边界 |
| 配置 | Debug 全平台构建及普通 unsigned iOS Release 编译 | 分发其他平台前补相应 Release、资源与设备验收 |
| 原生体验 | 双语、设备输入、VoiceOver、大字、冷启/中断/错误路径 | 执行 [平台矩阵](standards/platform-acceptance.md)，不以编译替代体验 |
| Harness 能力 | 开放 adapter 契约，Codex 固定版本全量清单与覆盖定义 | 按 [Harness 规范](standards/harness-integration.md)逐项实现/验证，不将最小闭环称完整支持 |
| 连接与信任 | 官方协议核对、配对/撤销、认证、授权、防重放、离线恢复设计 | 保持固定版本/schema与私有HTTPS信任边界，补设备撤销、蜂窝和离线证据 |
| 语音/素材 | 原生/开源替代方案、权限/成本/数据生命周期、后端能力边界 | 按 [多模态研究](../references/multimodal-research.md)实施单次显式语音探针，不预装大模型 |
| 数据与运维 | 当前本地文件边界、未来日志脱敏、保留/导出/删除和迁移/恢复 | 保留已实现的schema/单写者和删除去重边界，邀请beta前补备份/导出/迁移验收 |
| AI 协作 | 短任务卡、模块所有权、独立复审、精确提交 CI、PR 集成与回滚 | 使用下方任务契约；维护 release PR，TestFlight 单独批准 |

## 开发顺序

1. **F0 / 本轮前期建设**：需求与规范、官方/开源研究、性能/Release 门禁、可执行回归、独立复核和 CI 集成。只改变工程基础，不开通远程服务或收集音视频。
2. **F1 / 已有协议与安全研究**：用合成项目在 Mac 本机探测固定版本 app-server，核对会话、事件、审批、取消；选择首个受认证网络路径并补威胁模型。文字测试仅用于隔离传输问题。
3. **F2 / 手机真实闭环**：蜂窝网络 → 自己的 Mac → 真实执行 → 事件/审批/完成；断连和不确定提交不重复执行，未通过不扩大设备范围。
4. **F3 / 语音与随手用**：短语音 → 可纠正意图 → 已验证执行链路；系统快捷入口、完成通知和 Watch 短任务。一起验收权限、中断、双语、辅助功能和性能。
5. **F4 / 多模态与扩展**：图片后视频、服务器、实时语音/眼镜；每项独立证明能力、隐私、功耗与使用价值。按真实阻塞选择下一项。

F0 已接受，研究结果按需复用；不再把新的身份研究当作产品前置条件。首个产品切片将 F2 与 F3 的 iPhone 短语音、系统入口及通知路由一起交付，Watch 另行立项。当前选择的私有 Tailscale HTTPS、设备 bearer 与原生 Mac 主机见[信任与服务决策](decisions/device-trust-and-host-service.md)；尚未完成的 mTLS/CSR 持久化研究不阻塞这条路径。首个用户可用版本仍必须记录 R05 语音、R09 设备体验和相关网络的实际验收。所有阶段允许证据促使缩小范围或替换方案；不得为了“前期完备”无限增加无消费者的抽象层。

## AI 任务契约

开始编码前在 PR/任务中写一张简短任务卡，不复制整套规范：

```text
需求：R编号；用户触发与预期可观察结果
范围：允许修改的模块、现有边界、此次不实现的未来能力
依据：官方来源/核对日期；参考项目固定commit与许可；采用/拒绝理由
失败：权限拒绝、取消、断连、重复/乱序、输入/存储失败中的相关项
验证：同一输入的变更前后结果；回归命令；需要的SDK/设备/网络
资源：任务/上传/事件/重试的界限；性能预算与测量环境
恢复：配置/协议/数据兼容；回滚方式；未知结果如何向用户呈现
完成：独立diff复核、当前head CI、review threads、状态更新、PR集成
```

子 agent 只处理互不重叠的模块，由集成人复核；不能把 agent 自述当执行证据。新配置或性能阈值需解释依据，不能调宽预算来掩盖退化。数据格式变化先写迁移/失败恢复设计，保留旧版本可读样本并测试，不用删用户数据修复兼容性。
