# 产品需求基线 / Requirements

确认日期：2026-11-18。依据：项目所有者本轮明确的目标。本页定义要做什么；[项目状态](project-status.md)单独说明已经做到什么，研究和计划不能替代实现。

## 核心目标与主链路

Munie 是随身的个人 Agent 助理前台。用户离开电脑后，仍可通过 iPhone、Apple Watch 等设备，用语音及适合设备的交互，调用自己 Mac 上的 Codex，了解任务进展、继续指挥并取得真实结果；后续支持自己的服务器执行端。手机文字输入是必要的补充。生活中的提问、照片、拍摄和视频也应逐步成为任务输入，长期可由语音助理和智能眼镜提供连续上下文。后端架构开放给不同 harness，当前首先原生完整适配 Codex；语音理解层与执行层分别演进。

主链路：**快捷唤起 → 说出需求或提供素材 → 必要的澄清/授权 → Mac Codex 实际干活 → 简洁汇报 → 继续或结束**。AI 承担配置选择、上下文整理和结果总结；用户始终能理解执行对象、状态和后果。无感意味着操作少、上下文连续；录音、隐私与必要授权保持可感知、可控制。

首个可用里程碑限定为 iPhone ↔ Mac：明确配对与项目授权、真实 Codex 文字任务、短语音及纠正/取消/文字回退、权威进展与结果、知情审批、取消确认、同会话继续及不盲重发的恢复；在网络和设备可用时完成蜂窝验收。系统通知与 Shortcuts 提供相关入口。R16 的完整原生覆盖仍是长期目标，不作为无限扩大首片范围的理由；当前支持子集与缺口必须逐项可见。Watch 的短任务与反馈在主链路之后单独立项，其他平台保留现有基础。记录、搜索和草稿属于辅助能力，不再作为独立记事产品扩大范围。实际完成程度唯一见[项目状态](project-status.md)。

## 可追踪需求

P0 是首个远程闭环的必要条件；P1 逐步形成日常助理；P2 是需单独可行性验证的长期能力。表中均为要求，不是完成声明。

| ID / 优先级 | 用户需要 | 可观察验收 |
|---|---|---|
| R01 / P0 | 不在家也能使用 Mac Codex | 手机关闭 Wi-Fi、使用蜂窝网络，向已配对且清醒在线的 Mac 发起真实任务，取得可核对的执行结果；局域网成功单独记录 |
| R02 / P0 | 发起、继续和切换工作 | 在允许的项目中创建任务，按实际 thread/turn 继续；多项目的目标、待授权与结果互不串线；任意桌面会话接管须另验 |
| R03 / P0 | 一眼知道干到哪里 | 展示真实执行事件、等待授权、失败和完成；摘要能定位到对应任务及最新事件，不用模型猜测补充进度 |
| R04 / P0 | 复杂操作交给 AI | 已配对后的普通任务无需每次选择模型、网络地址或 shell；默认入口直达输入或最近任务；高级配置渐进披露 |
| R05 / P0 | 用语音更方便地下达任务 | 首个产品交互采用用户主动开始/停止的短语音；支持识别失败、纠正、取消与文字回退。Watch 使用系统听写/短交互，不能要求长篇键入；先做文字传输探针只算工程验收 |
| R06 / P0 | 稳定重连且不会重复干活 | 断网、切网、重复点击、客户端重启、Mac 重启与响应丢失均有证据；不确定的提交先核对，禁止盲目重放有副作用任务 |
| R07 / P0 | 安心交给自己的设备 | 配对、撤销、项目范围、最小权限、加密通道；Codex 凭据只留在执行主机；待授权动作准确绑定任务，拒绝与过期不被当成同意 |
| R08 / P0 | 能停止，也能解释失败 | 取消必须获得主机终态确认；失联时显示待确认，输入保留可恢复；Mac 睡眠/离线与 Codex 运行状态分开显示 |
| R09 / P0 | 轻快、原生、容易上手 | Apple 系统交互、English/简体中文、VoiceOver/大字/输入适配；性能按阶段测量且失败可见，初次上手不索取不需要的权限 |
| R10 / P1 | AI 主动汇报，少盯屏幕 | 完成/待授权/失败用系统通知提醒，点开回到原任务；通知隐去敏感内容、去重、尊重静音。进度摘要按需或有意义的状态变化生成 |
| R11 / P1 | 手表抬手说、迅速知结果 | 验证冷启动、锁屏、中断、配对/独立网络路径；短摘要与触觉/通知优先。语音播报须符合系统允许的会话和用户设置，不能承诺任意后台强制朗读 |
| R12 / P1 | 照片、拍摄、视频都能交给助理 | 权限按使用请求；上传前可确认/移除素材；大小、时长、格式、断点/失败、保留与删除有边界。按后端实测能力发送图片，视频需独立预处理和成本验收 |
| R13 / P1 | 执行端可扩到自己的服务器 | 主机标识、允许项目、会话与权限隔离；首个 Mac adapter 验证后再抽共享协议，不预建空插件体系 |
| R14 / P2 | 自然连续对话与眼镜上下文 | 对比原生语音与 Qwen 等语音理解层，评估智能眼镜硬件/SDK、实时音视频、延迟、耗电和许可；任何连续感知均显式 opt-in、可停止、可删除 |
| R15 / P2 | 多种主动触达方式 | 先验证系统通知，再评估按需语音/其他消息渠道；短信涉及服务商、费用、同意和送达机制，独立决策，不默认开通 |
| R16 / P0 | 原生、完整地远程使用 Codex | 固定支持的 Codex 版本与能力清单，覆盖会话、任务、事件、审批、配置、工具/附件等已公开能力；每项有实现和行为证据。不能把文字聊天或一个成功任务称为完整支持；设备上不能完整呈现的操作有明确转交路径 |
| R17 / P0 架构 / 后续适配 | 可接不同 harness，保留各自特性 | 公共语义 + capability 协商 + 原生能力扩展；Codex 特性不被最小公共接口抹掉。Claude Code、Pi、Hermes、OpenClaw、WorkBuddy、Qoder 等分别调研官方接口，不假设协议相同或当前已支持 |
| R18 / P0 设计 / P1 设备验收 | 充分利用 Apple 硬件，随时有掌控感 | iPhone Action button、Watch 系统快捷入口/支持机型的按键快捷指令、AirPods Siri/听筒与系统通知播报分别设计；一句话发任务并取得接受/进度/完成反馈。实测前台、后台、锁屏、耳机切换与通知关闭；无对应公开能力时提供同目标的系统替代入口 |
| R19 / P0 架构 / 分平台验收 | Apple 各类产品尽可能兼容通用，交互最直接 | 共享任务、权限、能力协商和接续语义；iPhone/iPad/Mac/Watch/TV/Vision 分别适配输入/导航与反馈。AirPods、Pencil、HomePod、CarPlay 等按公开接口/硬件/地区/审批条件评估，不能将“不支持”藏在静默空实现；完整复杂操作可明确接续到适合的设备 |

## 体验与成功标准

第一次配对允许一次性的解释与设置；之后的常用任务目标为从系统入口一次到达输入、输入后一次明确提交，复杂选择由上下文和合理默认值承担。高风险或有歧义的操作按真实需要澄清。用真实操作次数、完成率、纠错率和用户能否解释当前状态验收，不能用“像 Jarvis”替代指标。

近期开发者场景：在外询问多个项目进度、让 Codex 继续已授权工作、回答必要审批、接收结果摘要并追问。生活助理场景保留在需求中，按照片问答、短语音任务、视频理解逐片验证。每片记录原方法基线、节省步骤、响应分布和错误；不以演示成功推断全天可靠。
