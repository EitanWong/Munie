# Native desktop product runtime

Checked 2026-11-18. Product intent is [R04](../docs/requirements.md): one Mac app and one iPhone app, with no terminal setup. Actual execution evidence belongs in [status](../docs/project-status.md). This document records component and packaging choices, not distribution approval.

## Reuse and provenance

The native `MunieDesktop` app wraps the already [adopted Remodex](remodex-adoption.md) bridge and relay. It does not replace their secure transport, project policy, recovery or native Codex implementation. A bounded JSONL control channel reports actual host/account state; local account requests never become mobile RPC methods. The existing C guardian supervises the worker process group through owner death. The relay listens on loopback for the bridge and a selected private LAN address for the phone; no public listener, hosted deployment or Funnel is provisioned.

## Existing Codex settings

The bundled CLI uses its [native configuration and credential storage](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/login/src/auth/storage.rs). File credentials and the Keychain account slot are tied to the Codex home. Munie does not parse, duplicate, or change the user's credential storage. The host forwards an existing absolute `CODEX_HOME` when available in the app's launch context and otherwise leaves the default to Codex. It does not load shell startup files or propagate arbitrary terminal-only environment variables. A native successful configuration load does not establish that the selected endpoint accepts requests.

### Process policy prototype

The [native policy patch](codex-munie-stdio-policy.patch) targets public Codex source commit [`092d3ac`](https://github.com/openai/codex/tree/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d), Apache-2.0, with upstream license and notices preserved. This is a developer proof, not a substitute for the locked runtime archive. Its stdio-only opt-in disables startup plugin tasks, restoration of persisted remote control, MCP connections, and normal, legacy and executor hook registration in that process. The user's configuration and model provider still pass through the native loader. A restricted initializer returns `munieStdioPolicyVersion: 1`; stock and unrestricted processes omit it. The candidate refuses incompatible managed hook or nonempty MCP requirements instead of dropping them and continuing. The patch does not establish coverage of every native extension, OAuth, or keychain path.

Use the pinned [source archive](https://codeload.github.com/openai/codex/tar.gz/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d) (observed SHA-256 `79c8ea8547e1dd9969f63ef6b76a4fb0d1a024ef36c0c627fbcd2ffb658d9312`). Unpack under ignored `references/checkouts/` and apply the patch in order with `patch -p1 < ABSOLUTE_POLICY_PATCH` at the archive root. Then build from its `codex-rs` directory with Rust 1.95.0. The source archive's lock still lists the pre-release workspace version; run `cargo +1.95.0 check -p codex-cli --bin codex` to reconcile it before the locked build. The observed lock change was workspace packages from `0.0.0` to `0.162.1`, not third-party version selection. Then run `CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_DEV_INCREMENTAL=false cargo +1.95.0 build --locked -p codex-cli --bin codex`.

From the Munie root, run [the no-turn MCP probe](../scripts/fixtures/probe-codex-mcp-dispatch.py) with that binary, first without and then with `--restricted`. The MCP control must start exactly the configured synthetic process both before and after a reload; restricted mode must start neither while adopting both models. Starting a thread does not send model context.

The restricted Responses path verifies the final authenticated HTTPS request before sending context. A private replay record authenticates the local history and destination across process restarts. For the recognized official account path, the binding distinguishes the workspace, individual member and authentication mode while permitting bearer rotation. Missing or ambiguous authorization is rejected on the official route. Unverified old history remains readable but cannot be sent. Redirects and Responses WebSocket fallback are disabled in the restricted process; command-based provider auth is refused. A required Guardian policy that the restricted process cannot enforce fails closed. These restrictions do not apply to ordinary standalone Codex.

To package this exact local binary for developer verification, run `python3 scripts/prepare-desktop-runtime.py --policy-codex ABSOLUTE_BINARY --output FRESH_RESOURCE_DIR` and pass that directory as `MUNIE_DESKTOP_BUNDLE` to the Mac build. The [runtime lock](desktop-runtime-lock.json) pins the patch and this prebuilt binary; the digest does not establish byte-for-byte build reproducibility across machines. The embedding phase rejects either half of the preview (the pinned binary and its policy marker) on its own and does not allow archiving the preview. The guarded bridge requests the policy only in the native subprocess and requires an exact numeric version 1 from its private initialize RPC before sending `initialized` or opening pairing. Stock without the marker remains the default read-only backend; the marked preview also stays read-only. The marker is not an execution permission.

For the [managed-policy probe](../scripts/fixtures/probe-codex-managed-policy.py), use the same patched source and Cargo profile settings, but build `-p codex-app-server --bin codex-app-server` and pass that standalone debug binary. The probe uses the upstream debug-only managed-path override to load a temporary requirements file. It must observe both unrestricted controls initialize, both incompatible restricted startups exit 1 before acknowledgement, and the restricted process reject new threads after incompatible policy changes but accept a new thread after restoring compatible requirements. This verifies the shared native startup and fresh-thread configuration paths. It does not exercise host MDM discovery, the bundled entry point with real MDM, or an already-running turn.

The [hook](../scripts/fixtures/probe-codex-hook-dispatch.py), [installed-plugin](../scripts/fixtures/probe-codex-installed-plugin.py) and [bounded-approval](../scripts/fixtures/probe-codex-bounded-approval.py) probes with HTTP Responses reproduce the historical stdio-only checkpoint at `1b28c658`, not the current TLS and replay policy. Do not relax the current HTTPS or replay requirements to run them. The installed-plugin result remains historical, not a current positive control.

Run [the simulator loopback runner](../scripts/test-managed-relay-loopback.sh) with an explicit iOS simulator UUID and `MUNIE_MANAGED_PACKAGED_APP` pointing at the signed preview. The default run verifies project read, typed write rejection and reconnect. Pass `--approval` for the separate opt-in synthetic task using a disposable local TLS 1.3 Responses server and a peer-local fixture CA. The worker validates the CA file and digest under temporary state; normal launches do not inherit fixture trust. This mode verifies one-time approval, Stop and one original submission in the recovered native thread. Neither mode uses production managed ingress or replaces physical nearby enrollment.

## Packaging and limits

`prepare-desktop-runtime.py` and `package-desktop-runtime.py` are developer build tools. They verify fixed archives, extract named regular members, compile the existing guardian, install locked dependency archives with lifecycle scripts disabled, and assemble a fresh resource directory. `embed-desktop-runtime.py` checks every resource hash before copying it into the app and signs nested executables before outer signing. Runtime state, credentials and projects are never input directories. Product launch uses absolute bundled executables through `Process`; there is no fallback to `/opt/homebrew`, a shell, or global package installation.

`MUNIE_DESKTOP_COMPILE_ONLY=YES` is an explicit developer/CI compilation mode. It embeds no runtime and the app cannot claim readiness. It is rejected for archives. Local resource builds currently target Apple silicon; Intel archive provenance is not yet registered. Native Codex real-time voice runtime/dylibs are not packaged by this slice; iPhone opt-in short speech retains the existing bridge transcription path. No real audio acceptance is inferred.

Runtime notices/provenance, nested hardened signing/notarization and the existing Remodex distribution gates must all be resolved before distribution. Local bundling does not grant TestFlight approval. Nearby pairing does not establish an away-from-home network: ordinary users are not asked to configure VPN, ports or relay endpoints, and the new app explicitly marks away mode unavailable until a product-managed path is implemented.
