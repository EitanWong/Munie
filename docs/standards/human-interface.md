# 人机界面设计 / Human Interface Guidelines

本页是 Munie 的设计与 review 规则。以 [Apple HIG](https://developer.apple.com/design/human-interface-guidelines)及[官方来源登记](../../references/apple-platform-guidance.md)为依据；详细平台差异按需读取[平台验收](platform-acceptance.md)。新平台不是同一个手机界面的缩放版本。

## 内容与交互

优先 SwiftUI 系统导航、列表、表单、sheet、菜单和标准控件，让系统处理平台外观、语义和输入。自定义样式应解决具体用户需要，并验证可访问性和各平台行为；不要为了统一截图而覆盖系统材料或交互。

每屏保持清楚的主任务。Munie 首先帮助用户记录、找回与管理自己的内容；“已保存到本机”“已提交”“远端运行中”“已完成”只能对应真实状态。提供加载、空白、无结果、错误、重试和完成反馈；失败时保留可恢复的用户输入。破坏性动作明确作用对象，并提供适当确认或可行的撤销。

## 渐进披露

首次呈现主要任务及足够的上下文；次要动作放入系统菜单、详情或设置。标签说明将发生什么，用户能在当前上下文发现入口并返回。把高级选项延迟到需要时显示，避免在初次记录时要求配置 AI、连接或权限。

不能隐藏失败、执行状态、数据保存位置、破坏性后果或必要的隐私说明。渐进披露减少当前决策负担，不应增加寻找主要动作的步骤。文档也采用相同规则：[Agent 索引](../agent/README.md)只负责路由，专题文档展开细节，长日志留在产物中。

## 布局与视觉

使用安全区、系统字号、语义颜色与标准间距，允许内容决定高度。按窗口可用尺寸调整导航和信息密度；窄窗口、横竖屏、大字及长翻译不能遮挡保存/关闭等主要动作。列表与详情布局应保留选择和返回上下文。

同时检查浅色、深色、Increase Contrast 与 Reduce Motion。状态不能仅靠颜色表达。系统字体、图标和材料随 SDK 演进；采用新外观前核对最低版本及旧系统的可用路径。需要具体控件尺寸时查当期平台 HIG，避免把单个平台的数值当作全平台规则。

## 无障碍与本地化

使用语义 Button/Label 和清楚的可访问名称；装饰图像不应干扰朗读。主要任务应可由 VoiceOver 和目标平台的键盘、焦点或辅助输入完成。检查朗读顺序、焦点恢复、文本放大、对比度与运动偏好，使用 Accessibility Inspector 并补充实际操作。

所有产品文案同时维护 English 与简体中文 string catalog；包括错误、空状态、权限用途及可访问标签。测试更长翻译、复数、日期、数字与输入法。不要把 accessibility identifier 当作用户可见标签，也不要截断用户原文来让布局“通过”。

## UI PR 的证据

说明平台、窗口/设备、语言、主要与错误路径、输入方式及辅助功能。附有上下文的截图或运行记录，并把尚未执行的设备检查记录到[项目状态](../project-status.md)。编译、preview 和自动化 smoke 各自只能证明执行过的范围，不能替代完整 HIG 或设备验收。
