# 个人 AI 前台：首轮实验与访谈模板

日期：2026-11-16。配套《个人AI前台_LeanStartup执行手册.md》使用。
当前状态：全部待执行；预填部分是计划和假设，结果栏没有填入任何实际用户数据。
用法：复制对应小节开新记录；实验开始前固定门槛，结束后追加学习卡，保留原计划。

## 1. 一页产品假设：预填起点

- 本轮版本：HYPOTHESIS_VERSION。
- 决策日期：DATE。
- 时间上限：HOURS 小时；现金投入上限：BUDGET；超过时先复盘。
- 当前目标：自己日用 → 小范围独立使用 → 再决定是否商业化。
- 初始人群：经常离开桌面、会产生工作需求、使用 iPhone 的独立工作者；具体职业 SEGMENT。
- 触发：散步/通勤/家务时想到一件值得留下或处理的事。
- 工作：可靠交代，之后找得回、接得上。
- 首轮候选：A 随手捕捉并继续；B 带个人上下文提问；C 外出远程交办。
- 当前优先假设：先测试 A；若近期事实更支持 B/C，则据此改版并保留原因。
- 当前替代：ALTERNATIVE；不满的具体步骤：PAIN_STEP。
- 用户结果：OUTCOME；成功必须能由用户或产物确认。
- 首个入口：ENTRY；选择理由：EVIDENCE。
- 首个执行端：EXECUTOR；尚不承诺其他适配。
- 最大需求风险：用户是否真的回看并采用。
- 最大技术风险：TECH_RISK；最多投入 TECH_HOURS 小时验证。
- 最大信任风险：用户是否理解并能控制数据处理。
- 最先验证的假设：HYPOTHESIS。
- 相反证据长什么样：DISCONFIRMING_EVIDENCE。
- 本轮明确暂缓：DEFERRED_SCOPE。
- 第一渠道假设：CHANNEL；招募依据：RECRUITMENT_CRITERIA。
- 商业假设：VALUE_TO_PAY；成本、价格、续费尚未验证。

## 3. 招募与知情说明：草稿，尚未发送

### 访谈招募草稿

“我在研究一个问题：离开电脑时，临时想到要记录或处理的工作，你现在怎么做？

想找过去两周反复遇到这件事、使用 iPhone 的独立工作者聊约 30 分钟。主要了解你的实际做法和最近一次经历，不要求你喜欢我的方案，也不是产品推销。不需要展示敏感资料；是否录音会另行征求同意。如果方便，想约 TIME_SLOT。”

筛选时询问：

- 最近一次是什么时候？发生过多少次？
- 现在主要用什么办法？
- 方便用非敏感例子描述或展示吗？
- 职业/工作方式、设备组合是否符合本轮人群？
- 与创始人关系：RELATIONSHIP；招募来源：CHANNEL。

不因“不爱 AI”或使用竞品就排除；不把只夸想法、没有实际场景的人算成合格行为样本。

### 访谈开场说明

“今天想了解你的经历，没有正确答案。你可以跳过任何问题，随时结束。默认我只记必要笔记；如果希望录音，我会单独询问。笔记用于这次产品研究，按事先说明的期限保存。引用你的原话、公开内容或交给第三方模型处理前，会按约定获得相应授权。”

在接触真实参与者前填完：

| 项目 | 实际安排 |
|---|---|
| 联系人/反馈方式 | CONTACT |
| 收集哪些数据 | DATA_FIELDS |
| 存在哪里、谁能访问 | STORAGE_AND_ACCESS |
| 会用哪些服务/模型处理 | PROCESSORS_AND_PURPOSE |
| 保留与删除时间 | RETENTION_AND_DELETION |
| 如何撤回和提出删除 | WITHDRAWAL_CONTACT |
| 访谈报酬（如有） | COMPENSATION；与回答是否支持想法无关 |
| 录音是否同意 | CONSENT_AUDIO；未同意则不录 |
| 匿名引用是否同意 | CONSENT_QUOTE；与录音授权分开 |

### E2 服务原型邀请草稿

“我在试一个很窄的流程：你在外面想到一件要记下的事，通过 ENTRY 交代，随后会在 DELIVERY_PLACE 看到可以继续处理的记录。试用 7 天，范围是 SERVICE_SCOPE。

目前有些环节由我人工处理：HUMAN_STEPS。我能看到 DATA_SCOPE，数据去向与保留方式是 DATA_FLOW_AND_RETENTION。你可以只用非敏感内容，也可随时停止或要求按约定删除。这个版本还不能做 UNSUPPORTED。欢迎按自己的实际需求用；不要求每天凑次数。是否愿意试一周？”

人工环节、数据流和交付承诺必须先填真实安排。若处理来自旁人的内容，不能仅凭参与者愿意就认定所有相关授权均已具备。

## 4. 30 分钟访谈流程与记录

### 时间安排

- 0–3 分钟：说明目的、处理方式和授权，确认符合筛选条件。
- 3–15 分钟：最近一次事件的起因、过程、结果。
- 15–23 分钟：看当前办法，追问替代方案与损失。
- 23–27 分钟：追问不需要解决的情况与反例。
- 27–30 分钟：可展示一个简短概念；邀请明确下一步，记录真实承诺。

### 主问题

1. 上一次离开电脑时想到这类事情，具体是什么时候？
2. 当时想完成什么？哪一步最麻烦？
3. 后来怎么做？能展示去除敏感资料后的过程吗？
4. 没做好有什么后果？最终怎样补救？
5. 之前试过什么办法？为什么还不满意，或为什么已经足够好？
6. 过去两周发生过几次？哪些情境完全不会遇到？
7. 如果不使用手机/语音，你现在会选什么？
8. 最后才问：愿意提供一个非敏感任务、安排一次试用或完成一个必要设置吗？

少问“你觉得我的产品怎么样”；不把“愿意”算作已完成下一步。

### 单次记录

- 访谈编号：INTERVIEW_ID；日期：DATE；匿名用户编号：USER_ID。
- 职业/设备/渠道/创始人关系：SEGMENT_DEVICE_CHANNEL_RELATIONSHIP。
- 合格条件及依据：ELIGIBILITY。
- 最近一次事件：RECENT_EVENT。
- 现有替代、付出的钱或时间：WORKAROUND_AND_COST。
- 事件频率：FREQUENCY；估计依据和不确定性：UNCERTAINTY。
- 获准保留的原话：QUOTE。
- 观察到的具体操作：OBSERVED_BEHAVIOR。
- 自己的解释：INTERPRETATION。
- 其他可能解释：ALTERNATIVE_EXPLANATION。
- 反对当前假设的事实：COUNTEREVIDENCE。
- 下一步承诺：COMMITMENT；实际完成：FULFILLED_OR_PENDING。
- 是否需要跟进及时间：FOLLOW_UP；尚未自动发送任何消息。

- 要作的决策：是否值得把这一场景做成狭窄原生 MVP。
- 假设：合格用户不仅会输入，还会在没有研究催促时反复回来，并采用保存的结果。

- 人工与模型的处理范围：AUTHORIZED_PROCESSING。
- 事件记录：提交、可靠保存/接单、交付、查看、实际采用、失败、取消；标注研究提醒。
- 主要判断：至少 3/5 人，在首次使用之外的至少 2 个不同日期主动使用，并各有至少 1 次结果被实际采用。
- 采用的证据：例如进入真实待办、继续完成原任务、用于工作资料；仅打开记录不计。

- 次要观察：输入与采用之间的落差、操作耗时、可变费用、人工分钟数、信任障碍。
- 未达门槛时：区分无使用机会、入口难、交付没价值、技术故障和不信任；不自动开开发大单。
- 中止条件：参与者撤回、无法停止采集、数据失控或预算超出；按约定处理已有资料。
- 解释边界：人工服务的复用不能证明软件已自动化，也不能证明长期商业留存。

## 6. E3 配对入口比较卡：可选，待执行

- 假设：前端入口本身减少操作负担，而不降低可靠性。
- 对象：8 位合格用户；重复试次仍按 8 位独立用户解释。
- 对照：用户原方法；候选：PROTOTYPE_ENTRY。
- 任务对：TASK_PAIR；语句长度和难度尽量相当。
- 模型与网络控制：MODEL_AND_NETWORK；不能控制的因素记录。
- 顺序：一半先原方法、一半先原型，任务版本交替。
- 计时：从 START_EVENT 至可靠保存/接单 END_EVENT。
- 门槛：配对完成时间中位数至少降低 30%，任务质量不降低；失败率与重试同时审查。
- 算法：每人计算（原方法时间−原型时间）/原方法时间，再取改善比例中位数。失败样本保留，有效时间配对数单列；成功率或质量降低即不通过。
- 结果时延另测，不能把“接单”当成“办完”。
- 结论范围：探索性小样本；不推算整个市场的精确提升比例。

- 实际收款方式及适用发行规则：PAYMENT_AND_DISTRIBUTION。
- 拟接触的合格用户数：N；真实购买门槛：THRESHOLD。
- 区分：愿意付款 / 开始结账 / 真正支付 / 退款 / 后续续费。
- 渠道：CHANNEL；本轮只验证这个渠道的招募效果。
- 接触、回应、试用、安装、激活、复访、付费各人数：FUNNEL_COUNTS。
- 现金与创始人小时数：CASH_AND_HOURS。
- 是否有独立于创始人陪同的价值：INDEPENDENT_VALUE。
- 付费门槛未达时的下一动作：FAILURE_ACTION。
- 结论边界：首次付款不等于长期留存；朋友支持性购买需单列。

## 12. 第 14 天与每周决策备忘

每次只写一页，先看事实，再写解释。

1. 当前服务谁、解决哪件事：CURRENT_SEGMENT_AND_JOB。
2. 本轮投入了多少时间和现金：ACTUAL_APPETITE。
3. 新增最强证据三条：FACT_1 / FACT_2 / FACT_3。
4. 最强反例与未使用原因：COUNTEREVIDENCE。
5. 原假设及门槛是否达到，分子/分母是什么：RESULT。
6. 用户需要更多，还是我们只是想多做：VALUE_GAP。
7. 决定继续、缩窄、改变、暂停，还是只做自用：DECISION。
8. 下一轮唯一主要假设、最小实验、预定门槛：NEXT_EXPERIMENT。
9. 两个立刻可做的后续动作与日期：ACTION_1_DATE / ACTION_2_DATE。
10. 下次复盘时间：REVIEW_DATE。

填写前不必先做 Logo、所有设备入口、完整插件系统或长期架构。先把第一条可以被事实推翻的产品假设跑起来。
